# PRAXIS — Contractor operations overview

## Intended customer

Plumbing and trade contractors coordinating employees across service calls, renovations and construction sites. PRAXIS aims to connect the office's assignments with the field's progress, time and completion evidence.

This is a proposed product direction. No company is represented as a client, pilot participant or endorser.

## Business case

| Question for the owner | Planned capability |
| --- | --- |
| Who is working where today? | Project/site schedule with crew and employee assignments |
| Which jobs are delayed or blocked? | Dated progress updates, blocker ownership and follow-ups |
| What did each employee work on? | Job-linked time entries and supervisor approval |
| What has this project cost so far? | Approved labour and material costs compared with the project budget |
| Is the work actually complete? | Employee completion evidence followed by manager approval |

The first planned release focuses on these five needs. Quotes, customer-approved additional work, purchasing and invoice export are later modules. Payroll and live GPS are outside the first release.

## Service calls and projects

A short service call can have one work order and visit. A larger project groups multiple work orders, site visits, crews and budgets. Completing a visit does not automatically close a project or approve an invoice.

Intended workflow: request → project and site → scheduled crew → employee updates and time → completion submission → manager approval.

## What exists today

The local maintenance prototype demonstrates request review, follow-up ownership, technician workload, a demonstration scorecard and coordinator-confirmed allocation. Existing screenshots show this working foundation with simulated equipment-maintenance records.

Project management, crew scheduling, employee authentication, mobile work updates, timesheet approval and job costing remain to be implemented. No live multi-company service, app-store release or production deployment is claimed.

## Professional delivery target

A manager workspace and an employee phone experience, with authenticated roles, separate company data, attributable decisions, reliable backups and tested device behavior. French and English operational interfaces form part of the intended release.

Before any commercial pilot, the complete workflow, access controls, data recovery and device behavior must be validated. Source code, detailed architecture, internal rules and test fixtures remain private.

## Value validation

Interview a contractor about their current process before claiming product fit. A bounded pilot should measure schedule conflicts, missing job updates, time-approval delay, unresolved blockers and cost-record completeness against an agreed baseline.

All current records are simulated. No measured time savings, increased profitability, customer outcomes or pricing validation is asserted.

## Candidate v2 — From opportunity to project

A future tender workspace could connect saved public opportunities, bid/no-bid decisions, preparation checklists, amendment reviews and verified contract awards to PRAXIS project planning. This is a proposal inspired by [SEAO](https://seao.gouv.qc.ca/avis-du-jour) and [Quebec's tender preparation guidance](https://www.quebec.ca/gouvernement/faire-affaire-gouvernement/preparer-marches-publics/appel-offres).

No SEAO integration, live feed, automatic submission or government affiliation is implemented or claimed. Validate contractor v1 first, then assess a manual tender-to-project workflow before an external data connection.
